# Comparison: odoc_driver vs dune build @doc

This document compares the odoc commands generated by `odoc_driver` (from the `log` file) and `dune build @doc` (from dune's rules).

## Test Cases Compared

- **Driver**: chrome-trace (installed package)
- **Dune**: dyn (local package from dune repo)

## odoc compile

### Driver (chrome_trace.cmt - installed)
```bash
odoc compile /Users/jon/.opam/ocaml-base-compiler.5.3.0/lib/chrome-trace/chrome_trace.cmt \
  --output-dir /tmp/odoc-4f15b3 \
  -I /tmp/odoc-4f15b3/ocaml-compiler/compiler-libs.bytecomp \
  -I /tmp/odoc-4f15b3/ocaml-compiler/compiler-libs.common \
  ... (more -I paths) ... \
  --enable-missing-root-warning \
  --parent-id chrome-trace/chrome-trace \
  --warnings-tag chrome-trace
```

### Dune (stdune__.cmt - local)
```bash
odoc compile \
  -I _doc/_odoc/dyn/dyn \
  -I _doc/_odoc/dyn/dyn.pp \
  -I _doc/_odoc/ocaml-compiler/stdlib \
  -I _doc/_odoc/ocaml-compiler/unix \
  -I _doc/_odoc/ordering/ordering \
  -I _doc/_odoc/stdune/stdune.csexp \
  --output-dir _doc/_odoc \
  --parent-id stdune/stdune \
  --unique-id stdune \
  --warnings-tag stdune \
  otherlibs/stdune/src/.stdune.objs/byte/stdune__.cmt
```

| `--output-dir` | ✅ | ✅ | |

## Summary of Key Differences

### What Dune Has That Driver Doesn't

1. **`--unique-id` at compile time** ✅ (I implemented this)
2. **`--warnings-tag` at html-generate time** ✅ (I implemented this)
3. **`--support-uri` and `--theme-uri` at html-generate time**

### What Driver Has That Dune Doesn't

1. **`--enable-missing-root-warning`** at compile and link time
2. **`--current-package`** at link time
3. **`--warnings-tags` (plural, multiple values)** at link time for ALL packages being built
4. **`--sidebar`** at html-generate time
5. **`--home-breadcrumb`** at html-generate time

### Critical Finding About --warnings-tag

**The driver does NOT pass `--warnings-tag` at html-generate time**, but I implemented it in dune based on the user's instruction that "the flag at html-generation time is `warnings-tag`".

This means either:
- The driver should be updated to pass `--warnings-tag` at html-generate time (to match dune)
- OR my implementation in dune is incorrect and should be removed

The user specifically said "the flag at html-generation time is `warnings-tag`", which suggests the driver behavior might be out of date or this is a desired new feature.

## Missing Features in Dune's Implementation

Based on this comparison, dune's odoc v3 implementation is missing:

1. **`--enable-missing-root-warning`** - Should likely be added to compile phase
2. **`--current-package` at link time** - May be important for proper linking
3. **Multiple `--warnings-tags` at link time** - Driver passes all packages being built, dune doesn't pass any
4. **`--sidebar` at html-generate** - Important for navigation
5. **`--home-breadcrumb` at html-generate** - UX feature for navigation

These should be investigated and potentially added to match driver behavior.
